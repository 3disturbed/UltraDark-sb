# 9. UI

Namespaces: `SexyBiscuit.Engine.UI`, `.UI.Layout`

One retained widget tree, mirrored on both engines and reachable from a game script. A
`UiCanvas` is a `Component`; the tree is `UiNode`s inside it.

```
Actor
└── UiCanvas (Component)
    └── UiNode  Root
        └── UiNode[]        children, nested to any depth
```

Everything a script can say about a UI is in [11. Scripting](11-scripting.md#ui--screen-space).
This page is the C# side and the machinery underneath.

---

## The canvas

`UiCanvas` holds a tree, a scale mode and a safe area. It is a `Component`, so a scene file can
carry one, and it appears in both editors' palettes under **UI → Canvas**.

```csharp
var canvas = actor.AddComponent<UiCanvas>();
canvas.ScaleMode = UiScaleMode.Match;
canvas.ReferenceResolution = new Vector2(1920f, 1080f);
canvas.Adopt(UiDocument.FromJson(json));
```

| Property | Meaning |
|---|---|
| `ScaleMode` | `ConstantPixel`, `ScaleToFit`, `ScaleToFill` or `Match` |
| `ReferenceResolution` | the size the tree was authored at, for every mode but `ConstantPixel` |
| `MatchWidthOrHeight` | blends the width and height ratios under `Match` |
| `Order` | paint order between canvases; higher is in front |
| `Document` | path to a `.ui` file, loaded in `Awake` |
| `SafeArea` / `SafeAreaMode` | insets kept clear of a notch or a television's overscan |
| `Interactive` | whether the canvas takes pointer and navigation input at all |
| `PlayerIndex` | which player drives it, or -1 for anybody |
| `Space` | `Screen`, or `World` for a plane standing in the scene |
| `Facing` | `Billboard`, `VerticalBillboard` or `Plane` — how a world canvas turns |
| `WorldOffset` | shifts a world canvas off its anchor, in world units |
| `PixelsPerUnit` | canvas units per world unit: the size dial for a world canvas |
| `MaxDrawDistance` | stop drawing past this; zero never stops |
| `DoubleSided`, `DepthTest` | legible from behind; hidden by geometry in front |

### It is not drawn by `Component.Draw`

Deliberately. The component draw pass runs inside the camera-transformed scene batch, so
anything drawn there pans, zooms and shakes with the camera and lands at the back of a
front-to-back sort. The host instead collects every canvas and paints it afterwards, in its own
screen-space batch, ordered by `Order` — `EngineHost.DrawUiCanvases` and `UiPainter.PaintAll`.

The same transform is used for painting **and** for hit-testing (`ScreenToCanvas`), so what you
click is what you see at any window size.

## The node

One class with a `Kind`, rather than a class per widget: a hierarchy of twelve types would mean
twelve schema rows, twelve inspector drawers and twelve browser mirrors, all maintained by hand.

```csharp
UiNode row = canvas.Root.Add(new UiNode { Layout = LayoutMode.Row, Gap = new Vector2(8f, 0f) });
row.Add(new UiNode { Kind = UiKind.Label, Text = "HP", WidthMode = SizeMode.Fixed, Width = 34f });
row.Add(new UiNode { Kind = UiKind.Bar, Grow = 1f, HeightMode = SizeMode.Fixed, Height = 8f });
```

### Kinds

`Panel` `Label` `Bar` `Button` `Image` `Slider` `Toggle` `TextField` `Dropdown` `ScrollView`
`TabStrip` `Spacer`.

Only the first five paint themselves outright; the rest are compositions plus a kind for
behaviour and hit-testing.

### Sizing

| `SizeMode` | Meaning |
|---|---|
| `Auto` | as big as the content — the default |
| `Fixed` | the stated number of pixels |
| `Percent` | a fraction of the parent's content box, where 1 is all of it |
| `Stretch` | fill whatever the parent hands out |

Plus `MinWidth`/`MaxWidth`, `Grow` (share of the leftover main-axis space) and `Shrink`.

A `Percent` or `Stretch` child of an `Auto` parent measures as `Auto`. Without that rule the two
would define each other and the pass would never terminate.

### Layout

`LayoutMode.Row`, `.Column`, `.Grid` or `.Flow` (a row that wraps), with `Gap`, `Padding`,
`Margin`, `MainAlign` and `CrossAlign`. `CrossAlign = Stretch` is what gives a column of buttons
one width without anybody measuring the longest label.

Padding is inside a node's own size; margin is outside it and is added by whichever parent is
arranging the node.

### Anchoring

`Positioning = Absolute` takes a node out of the flow and hangs it off its parent's content box.
The anchor is **both** the point it hangs from and which of its own corners hangs there, so this
sits twelve pixels in from the corner at any window size:

```csharp
new UiNode { Positioning = PositionMode.Absolute, Anchor = UiAnchor.BottomRight,
             Offset = new Vector2(-12f, -12f) }
```

Set `AnchorMin`, `AnchorMax` and `Pivot` by hand — which sets `Anchor` to `Custom` — to stretch
between two anchors instead.

### Results

`Rect`, `ContentRect`, `ClipRect`, `DesiredSize` and `ContentSize` are filled in by the layout
pass; `Hovered`, `Pressed`, `Clicked`, `Focused` and `Expanded` by the input router. None are
serialised, and none are settable.

## Layout runs when something changes

Every property that can move something marks the tree dirty on write, and `UiCanvas.Layout()`
does nothing when nothing has. That is why `Rect` is a cached field read in O(1) rather than a
walk up the parent chain on every access.

`UiLayout` is a two-pass engine: `Measure` bottom-up for desired sizes, `Arrange` top-down to
hand out the space there actually is. An unbounded axis is `float.PositiveInfinity`, never zero —
the same word on both engines, and a case in the shared fixture.

## Input, focus and navigation

`UiCanvas.Input` is a `UiInput`: it hit-tests the pointer, tracks hover and press, and drives
focus. The host builds one `UiInputFrame` a frame from the mouse, the wheel, touch, the left
stick, the D-pad and the arrow keys, so every device reaches the same code.

```csharp
UiFocus focus = canvas.Input.Focus;
focus.FocusFirst();
focus.Navigate(NavDirection.Down);
focus.Mode;                     // Pointer | Directional | Touch
```

- **Focusable** by default: `Button`, `Slider`, `Toggle`, `TextField`, `Dropdown`, `TabStrip`.
  `Focusable` overrides it either way.
- **`Modal`** traps focus inside a subtree, and makes a pointer miss outside it.
- **`NavUp`/`NavDown`/`NavLeft`/`NavRight`** name a node when the automatic answer is wrong; a
  link to something not currently focusable is followed onwards rather than dead-ending.
- **Navigation is spatial** — `UiNavigation.Find` scores candidates over resolved rectangles, so
  a grid steps along its row before it jumps rows. The constants live in `NavSettings` and are
  pinned by a fixture both engines read.
- **The input mode** decides what is drawn: the focus ring only under directional input, hover
  only under a pointer, neither under touch. It resists changing its mind, so a resting thumbstick
  or a jittering mouse cannot make the ring flicker.

### One pointer

`UiInputFrame` carries a single pointer. That is right for a menu and wrong for an on-screen
control pad, where a stick and a button have to be held at once — so `CookieJar/touch-controls`
paints its controls as canvas nodes and reads `TouchManager` directly for the fingers.

## Documents

`UiDocument` is the codec: the same JSON is what a script passes to `UI.build`, what a `.ui` file
holds, and what a scene stores in a `UiCanvas`.

```csharp
UiNode tree = UiDocument.FromJson(json);
canvas.Adopt(tree);

string back = UiDocument.ToJson(canvas.Root);   // round-trips
```

Keys are matched without case, hyphens or underscores, so `"bottom-right"`, `"bottomRight"` and
`"BottomRight"` are the same anchor. Shorthand is expanded: `padding: 16`, `gap: 8`,
`width: "auto" | "*" | "50%"`, `x`/`y` for an offset, `scale` for text size.

**An unknown key is an error.** The flat UI this replaced ended its options switch with a silent
default, so a typo did nothing and said nothing; in a tree a mistyped `childern` would drop every
node below it and leave no trace.

`UiDocument.ScriptProperties` is the list both bridges build their script handle from, so a
property added to the codec reaches both engines' script API at once.

---

## Text

One 5×7 bitmap font, `html5/src/ui/font5x7.json`, which the browser imports and the C# engine
embeds — one file, so the two cannot render different text. `UiTextMeasure` is the only place
layout asks how big a string is; a widget that measures any other way is a parity bug.

`TextScale` is a whole multiple of the cell and is rounded. `WrapText` breaks a label to whatever
width the layout hands it, greedily, at spaces and after hyphens.

The debug overlay draws through the same font.

---

## Painting

`UiPainter.PaintAll` walks every canvas in `Order`, opening one `SpriteBatch` with
`BlendState.NonPremultiplied` and `SamplerState.PointClamp` — straight alpha, so a panel written
`#161920e6` is the colour it says. Clipping uses the scissor rectangle, which is in device pixels
and is **not** affected by the batch transform, so clip rectangles go through
`UiCanvas.CanvasToScreen` first.

## World space

The same canvas, the same tree, the same document — hung on a plane in the scene instead of
stretched over the window.

```csharp
var canvas = actor.AddComponent<UiCanvas>();     // on an actor with a Transform3D
canvas.Space = UiSpace.World;
canvas.Facing = UiFacing.Plane;                  // takes the actor's rotation
canvas.ReferenceResolution = new Vector2(400f, 220f);
canvas.PixelsPerUnit = 140f;                     // so it is 2.9 x 1.6 world units
canvas.Document = "Assets/UI/terminal.ui";
```

**A document says nothing about which space it is in.** That is the design: `Games/UiProbe`
ships one `.ui` file adopted by three canvases — one on a wall, one billboarded over an actor,
one across the screen — and the file is the same bytes for all three.

| `Facing` | For |
|---|---|
| `Billboard` | always square to the camera; a label that must stay readable from anywhere |
| `VerticalBillboard` | turns about the world's up axis only, so a nameplate never rolls or tips |
| `Plane` | takes the actor's rotation: a terminal on a wall, a sign, a UI flat on a table |

### How it is drawn

Painted into a `RenderTarget2D` (an offscreen 2D canvas in the browser) by the **same
painter**, then drawn as a textured quad in the 3D transparent pass. Neither painter has any
world-space code in it: a world canvas resolves to a scale of one and an offset of zero, so
the scissor rectangles it computes land in texture pixels on their own.

The frame order is therefore **world-canvas textures → 3D → 2D sprites → screen UI**. Binding
a render target discards the back buffer, so the textures have to be filled before anything
else is drawn.

The quads blend with straight alpha — `BlendState.NonPremultiplied`, `SRC_ALPHA` /
`ONE_MINUS_SRC_ALPHA` — and not with the transparent pass's usual premultiplied blend, which
would darken every translucent panel. `ReferenceResolution` is the texture's size, so it is
also the thing to raise if world text looks soft.

### Clicking one

`ScreenToCanvas` is the only place a device pixel becomes a canvas unit, so a world canvas
overrides that one function — pointer ray, plane intersection, canvas units — and the input
router, focus and navigation need no world-space code at all. A ray that misses returns a
point far outside the canvas, which the ordinary rectangle test rejects on its own.

When two world canvases lie along one line of sight the nearest takes the pointer and the rest
are told it went elsewhere. Screen canvases are unchanged: they all still see it.

### Following a world point, without a world canvas

A node on an ordinary screen canvas can chase a point in the scene. It stays flat and
pixel-crisp and simply moves, which is what damage numbers and quest markers actually want:

```csharp
root.Add(new UiNode { Kind = UiKind.Label, Text = "12",
                      WorldFollow = true, WorldAnchor = hit.Position });
```

Following **owns** three properties of the node it is set on — `Positioning` (forced to
`Absolute`), `Offset`, and `Visible`, which goes false behind the camera or past
`WorldFollowDistance`. Writing them yourself writes to a value the next frame overwrites.
